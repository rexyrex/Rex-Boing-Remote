See what your servers did while your Mac was asleep.

**History**
- Every dashboard has a History card: the last 15 minutes, 4 hours or 48 hours of CPU (with its peaks), memory, GPU, temperature, power, network and disk. Point at a moment for the readings then and the busiest processes of that quarter hour.
- New: **Keep history while this Mac is away** (Settings › Servers). The agent keeps sampling on the server as a service of your user: a systemd user service on Linux, a LaunchAgent on macOS, a Scheduled Task at sign-in on Windows. Still no root and no port: it answers only on a socket (or named pipe) that only your user can reach, and saves its history in its own folder so it survives restarts.
- On reconnect the agent sends what it kept, so the graphs pick up where you left off instead of starting empty.
- On Linux, user services stop at logout unless lingering is on. The agent turns it on where it may, and otherwise tells you the one command that does (`sudo loginctl enable-linger <you>`).
- Turning it off, or removing the agent, removes the service and the history it kept.

**Agents**
- New commands: `serve`, `install-service`, `uninstall-service`. The restricted key may run the last two; `serve` only runs locally. `doctor` reports whether background history is running.
- `upgrade` restarts a running background agent on the new version, keeping its history.
- The macOS agent now accepts exactly the same commands over the restricted key as the Go agent, in exactly the same forms.
- The protocol gains an optional `history` message (PROTOCOL.md, "Background history"). Older apps ignore it; older agents never send it.

**Also**
- `--demo` runs the app with made-up servers played from recordings, for trying it without servers of your own. The README's pictures are drawn from it.

The Windows background service has been built and tested on GitHub's Windows runners, not yet on a range of real PCs. Reports are very welcome.
